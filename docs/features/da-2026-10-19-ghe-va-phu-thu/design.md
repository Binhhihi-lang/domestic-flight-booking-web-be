# Thiết kế — Phụ thu nâng hạng ghế & sửa lỗi giao diện ghế

**Ngày:** 19/10/2026
**Nhánh:** `da` (cả BE và FE)
**Trạng thái:** Chờ duyệt

---

## 1. Vì sao làm việc này

Khách mua vé hạng phổ thông hiện có thể chọn ghế hạng thương gia mà **không bị tính thêm tiền**. DB v0.5 đã thiết kế sẵn chuỗi snapshot phụ thu (`flight_seats.seat_surcharge` → `seat_holds.surcharge_at_booking` → `bookings.seat_surcharge_amount`), nhưng **thiếu tầng cấu hình gốc**: không có nơi nào định nghĩa "nâng từ hạng vé X lên ghế hạng Y thì phụ thu bao nhiêu".

Đồng thời lưới ghế admin có 6 lỗi khiến ADMIN không dùng được chức năng màu vừa thêm ở v0.5.

## 2. Mục tiêu

1. Có **bảng cấu hình phụ thu nâng hạng** dùng chung cho mọi chuyến, ADMIN quản lý qua màn CRUD.
2. Sửa **6 lỗi giao diện lưới ghế** để `color_hex` thực sự phát huy tác dụng.
3. Hoàn thiện **CRUD loại ghế** để ADMIN tìm được đường vào và chọn màu trực quan.

## 3. Không làm trong đợt này (non-goals)

- **Không** làm Flight CRUD, sinh Seat Inventory, API chọn ghế, tính tiền booking. Những việc đó thuộc Phase 2/3 — BE hiện chưa có `FlightService`/`FlightController`, chỉ có entity.
- **Không** thêm `fare_class` FIRST. Giữ 3 hạng: ECONOMY, PREMIUM_ECONOMY, BUSINESS.
- **Không** đổi cột `flight_seats.seat_surcharge` thành nullable.
- **Không** làm màn chọn ghế phía khách.

## 5. Thiết kế

### 5.1 Bảng `seat_class_surcharges` (migration V14)

```sql
CREATE TABLE seat_class_surcharges (
    id          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    from_class  VARCHAR(20)   NOT NULL,   -- hạng VÉ khách mua
    to_class    VARCHAR(20)   NOT NULL,   -- hạng GHẾ vật lý
    surcharge   NUMERIC(12,2) NOT NULL DEFAULT 0,
    is_active   BOOLEAN       NOT NULL DEFAULT true,
    is_deleted  BOOLEAN       NOT NULL DEFAULT false,
    deleted_at  TIMESTAMPTZ,
    created_at  TIMESTAMPTZ   NOT NULL DEFAULT now(),
    updated_at  TIMESTAMPTZ   NOT NULL DEFAULT now(),

    CONSTRAINT chk_surcharge_from CHECK (from_class IN ('ECONOMY','BUSINESS','FIRST')),
    CONSTRAINT chk_surcharge_to   CHECK (to_class   IN ('ECONOMY','BUSINESS','FIRST')),
    CONSTRAINT chk_surcharge_non_negative CHECK (surcharge >= 0)
);

-- Chỉ một dòng sống cho mỗi cặp (from, to)
CREATE UNIQUE INDEX uq_seat_class_surcharges_pair
    ON seat_class_surcharges (from_class, to_class)
    WHERE is_deleted = false;
```

**Vì sao dùng partial unique index** thay vì `UNIQUE` thường: theo BR-LIST-04 của dự án, bản ghi xóa mềm vẫn nằm lại để tra lịch sử. `UNIQUE` thường sẽ chặn ADMIN tạo lại cặp đã từng xóa.

**Seed 6 dòng:**

| from_class | to_class | surcharge | Ý nghĩa |
|---|---|---|---|
| ECONOMY | ECONOMY | 0 | Ngồi đúng hạng |
| ECONOMY | BUSINESS | 500.000 | Nâng hạng |
| ECONOMY | FIRST | 1.200.000 | Nâng hạng |
| BUSINESS | ECONOMY | 0 | Hạ hạng — cho phép, không hoàn |
| BUSINESS | FIRST | 700.000 | Nâng hạng |
| FIRST | FIRST | 0 | Ngồi đúng hạng |

**Không seed** `FIRST → ECONOMY` và `FIRST → BUSINESS`. Theo quyết định #8, cặp chưa cấu hình nghĩa là **chưa có chính sách** — Phase 2 phải từ chối cho chọn ghế đó, KHÔNG được mặc định 0. Nếu ADMIN muốn cho FIRST hạ hạng xuống ECONOMY miễn phí thì phải tạo dòng `surcharge = 0` tường minh.

> **Phân biệt hai trạng thái — quan trọng:**
> - **Không có dòng** = chưa cấu hình → không được bán ghế đó.
> - **Có dòng với `surcharge = 0`** = cố ý miễn phí.
>
> Nếu gộp hai trạng thái này, ADMIN xóa nhầm dòng `ECONOMY → BUSINESS` sẽ khiến khách bay thương gia miễn phí mà không có cảnh báo.

**Dùng lại `BaseCrudController` + `BaseCrudService`** — không viết lại. Chỉ cần:
- Entity `SeatClassSurcharge`
- `SeatClassSurchargeRequest` / `SeatClassSurchargeResponse`
- `SeatClassSurchargeMapper` (MapStruct)
- `SeatClassSurchargeRepository`
- `SeatClassSurchargeService extends BaseCrudService<...>`
- `SeatClassSurchargeController extends BaseCrudController<...>`

**Request DTO:**

```java
public record SeatClassSurchargeRequest(
        @NotBlank @Pattern(regexp = "ECONOMY|BUSINESS|FIRST") String fromClass,
        @NotBlank @Pattern(regexp = "ECONOMY|BUSINESS|FIRST") String toClass,
        @NotNull @DecimalMin("0") BigDecimal surcharge,
        @Pattern(regexp = "(?i)ACTIVE|INACTIVE") String status
) {}
```

- `fromClass` / `toClass`: chuỗi, validate bằng `@Pattern`. Service ép `toUpperCase()` trước khi lưu (theo khuôn `SeatTypeService`).
- `status`: nhận trong body giống `SeatTypeRequest`; không gửi thì mặc định `ACTIVE`. Endpoint `/active` chỉ dùng cho toggle nhanh.
- Sửa bản ghi **được phép đổi** `fromClass`/`toClass` (quyết định #9) → `updateEntity` kiểm trùng cặp như `createEntity`, loại trừ chính id đang sửa.

**Response:**

```json
{
  "id": 2,
  "from_class": "ECONOMY",
  "to_class": "BUSINESS",
  "surcharge": 500000,
  "status": "ACTIVE"
}
```

**Kiểm trùng cặp — dùng repository method:**

```java
boolean existsByFromClassAndToClassAndIsDeletedFalse(SeatClass fromClass, SeatClass toClass);
boolean existsByFromClassAndToClassAndIsDeletedFalseAndIdNot(SeatClass f, SeatClass t, Long id);
```

**Ràng buộc khi tạo/sửa → `1006` (trùng cặp) / `1001` (sai validate):**
- Trùng cặp `(from_class, to_class)` với bản ghi chưa xóa.
- `surcharge < 0` → `1001` (validate DTO).
- `from_class`/`to_class` ngoài 3 giá trị → `1001` (validate DTO).

**Ràng buộc xóa → `1006`:** không có. Bảng này không bị bảng nào tham chiếu.

> ⚠️ **`@PreAuthorize` cho 2 method bulk phải tự khai ở lớp con.** `BaseCrudController` không gắn annotation quyền lên `bulkToggle`/`bulkDelete` (javadoc của lớp ghi rõ). Thiếu thì bulk chỉ cần `authenticated` là gọi được — hở quyền so với CRUD đơn lẻ.

### 5.3 Luồng dùng ở Phase 2 (ghi lại, chưa code)

```
Tạo Seat Inventory cho chuyến:
  for each aircraft_seat:
    fromClass = fare_class.seat_class của các fare_class trên chuyến
    toClass   = aircraft_seat.seat_type.seat_class
    policy    = seat_class_surcharges.find(fromClass, toClass)
    if (policy == null)
        → KHÔNG bán ghế này cho hạng vé đó (chưa có chính sách)
    else
        flight_seat.seat_surcharge = policy.surcharge
```

Ghi chú thiết kế: một chuyến có nhiều `fare_class` nhưng `flight_seat` là **vật lý**, không gắn với hạng vé. Vì vậy `flight_seats.seat_surcharge` chỉ có thể lưu **một** con số. Phase 2 sẽ cần quyết định: lấy phụ thu theo `fare_class` thấp nhất, hay tính phụ thu **lúc khách chọn ghế** bằng cách tra bảng cấu hình. → **Để Phase 2 quyết**, ghi vào tài liệu để không quên.

**Lưu ý về ECONOMY và PREMIUM_ECONOMY** (hệ quả quyết định #7): hai `fare_class` này cùng `seat_class = ECONOMY`, nên tra cùng một dòng cấu hình và trả cùng phụ thu. Nếu sau này cần phụ thu khác nhau giữa hai hạng vé này thì phải đổi cột `from_class` thành `fare_class_id` — đó là thay đổi schema, cần migration riêng.

### 5.4 Sửa lỗi giao diện lưới ghế (FE)

| # | Lỗi | Cách sửa |
|---|---|---|
| 1 | Tô màu theo `seat_class`, bỏ qua `color_hex` | `classOf()` → `cellStyle()` trả `background` từ `seat_type.color_hex`, fallback theo `seat_class` khi null |
| 2 | Chữ trắng cố định trên nền sáng | Tính độ tương phản WCAG, chọn `#fff` hoặc `#111` |
| 3 | Không có legend | Thêm dải legend dưới lưới: ô màu + tên loại ghế |
| 4 | `aria-label` đọc mã thay vì tên | Dùng `seat_type_name` |
| 5 | Không có `:focus-visible` | Thêm outline rõ ràng |
| 6 | `find()` trong vòng lặp lồng → O(n²) | Precompute `Map<number, SeatType>` và `Map<string, AircraftSeat>` trong `computed()` |

**Công thức tương phản — WCAG 2.1 đầy đủ (có gamma linearization):**

```
// 1. Chuẩn hoá kênh màu về [0,1]
c = channel / 255

// 2. Linear hoá sRGB — BƯỚC KHÔNG ĐƯỢC BỎ
c_lin = c <= 0.03928 ? c / 12.92 : ((c + 0.055) / 1.055) ^ 2.4

// 3. Độ sáng tương đối
L = 0.2126 * R_lin + 0.7152 * G_lin + 0.0722 * B_lin

// 4. Tỉ lệ tương phản
contrast = (L_light + 0.05) / (L_dark + 0.05)
```

Chọn chữ trắng nếu `contrast(white, bg) >= 4.5`, ngược lại chữ đen. Tính **một lần** cho mỗi loại ghế, không tính mỗi ô.

> ⚠️ **Bỏ bước 2 (gamma) là sai.** Dùng công thức tuyến tính sẽ tính ra độ sáng lệch đáng kể. Ví dụ màu `#90CAF9` (màu `ECO` trong mock):
> - Tính đúng: `L ≈ 0.592` → contrast với trắng `≈ 1.62` → **chọn chữ đen** (contrast 11.99)
> - Tính sai (bỏ gamma): `L ≈ 0.745` → contrast với trắng `≈ 1.34` → vẫn chọn chữ đen, nhưng con số sai và sẽ sai ở các màu khác
>
> Phải có unit test khẳng định `#90CAF9` → chữ đen.

**Legend — nguồn dữ liệu:**

Lấy từ **các loại ghế có mặt trong sơ đồ đang xem**, không lấy toàn bộ `seatTypes`. Vì:
- `seatTypes` truyền vào `SeatGrid` gồm cả loại `INACTIVE` — hiện trong legend là gây nhầm.
- Loại ghế không có ghế nào trên sơ đồ thì không cần chú thích.

Với loại ghế `color_hex = null`: legend hiện ô màu **mặc định theo `seat_class`** (cùng logic fallback với lưới) và ghi thêm nhãn "mặc định" để ADMIN biết màu đó không do mình đặt.

**Áp dụng màu — dùng `[style]` binding, không dùng class:**

Màu là dữ liệu động (từ DB), không phải tập hữu hạn → không sinh được class. Dùng:
```html
<button [style.background]="cellBackground(seat)"
        [style.color]="cellTextColor(seat)">
```
CSS `.cell--economy/.cell--business/.cell--first` **giữ lại** làm fallback khi `color_hex = null`.

### 5.5 Hoàn thiện CRUD loại ghế (FE)

| # | Thiếu | Cách sửa |
|---|---|---|
| 1 | Không có link sidebar | Thêm vào nhóm "Danh mục hàng không": `{ path: '/admin/seat-types', label: 'Loại ghế', icon: 'event_seat', adminOnly: true }` |
| 2 | Ô màu chỉ là `type: 'text'` | Thêm `CrudFieldType = 'color'`; render `<input type="color">` + ô hex đồng bộ 2 chiều |
| 3 | Bảng không có cột màu | Thêm `kind: 'color'` vào `CrudColumn`; render ô vuông màu + mã hex |

**Chi tiết `type: 'color'`:**

- `<input type="color">` **không biểu diễn được** trạng thái "không có màu" — nó luôn trả `#000000`. Vì vậy cần thêm nút **"Bỏ màu"** cạnh ô.
- Giá trị rỗng lưu là **`null`**, không phải `''`. Lý do: BE validate `@Pattern(regexp = "^#[0-9A-Fa-f]{6}$")` — chuỗi rỗng sẽ **trượt** validate; `null` mới hợp lệ.
- `buildDraft()` hiện dùng `defaultFor(field)` trả `''` cho mọi type không khớp. Cần thêm nhánh `case 'color': return null;`.
- Khi người dùng chọn màu từ picker → lưu `#rrggbb` (chữ thường từ browser), nhưng hiển thị ô hex chữ HOA. BE chuẩn hoá `toUpperCase()` trong `normalizeColor()` — đã có sẵn.

**Chi tiết `kind: 'color'`:**

- `color_hex` có giá trị → ô vuông màu + mã hex bên cạnh.
- `color_hex = null` → ô vuông nền chéo (hoặc viền đứt) + chữ **"Mặc định"**. Không để trống hoàn toàn, vì ADMIN cần phân biệt "chưa đặt màu" với "lỗi render".
